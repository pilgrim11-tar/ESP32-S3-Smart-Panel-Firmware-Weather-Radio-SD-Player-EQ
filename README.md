# 86switch_onoff_ai

Firmware for ESP32-S3 4848S040 (480x480, LVGL) with:
- Home weather/time screen
- Internet radio
- SD player with albums
- Donor mic panel integration
- Alarm and voice controls

## Architecture

Entry point:
- `86switch_onoff_ai.ino`: board/display/touch init, LVGL loop.

Core app:
- `doMain.cpp/.h`: UI orchestration, screen logic, app state.

Service modules:
- `radio_vendor.*`: radio playback backend.
- `sd_vendor.*`: SD library scan, album/track navigation.
- `mic_remote_client.*`: donor mic board API client.
- `net_worker.*`: single network worker + queue/mutex for HTTP/TLS serialization.
- `wifi_manager.*`: Wi-Fi connect flow, NTP/time helpers, persisted Wi-Fi settings.
- `wifi_ui_controller.*`: Wi-Fi UI texts/helpers.
- `power_manager.*`: screen sleep/wake brightness state logic.
- `app_settings.h`: centralized runtime constants (sleep, brightness, mic windows).
- `wake_logic.*`: donor-sound wake decision logic.
- `weather_visuals.*`, `weather_sd_assets.*`, `home_bg_sd_assets.*`: weather icons/background assets from SD.
- `speaker_tone.*`: tone/alarm output.

Lifecycle (high level):
1. `.ino` initializes hardware and LVGL.
2. `init_light()` in `doMain.cpp` initializes service modules.
3. Wi-Fi connect task starts (if credentials exist).
4. After Wi-Fi success, NTP task and weather task run.
5. Main UI loop coordinates Radio/SD/Power/Mic states.

## Screen Flow

- `Screen1` Home: weather, date/time, quick launch buttons (`Radio`, `Player`, `On`, `Off`).
- `Screen10` Settings: Wi-Fi/city/volume/backlight + media entry.
- `Screen11` Radio: internet station controls.
- `Screen12` Assistant/Sound: VU/equalizer and mic donor status.
- `Screen13` Alarm: alarm on/off, time adjust, melody `1/2/3`.
- Dynamic `Media` screen: SD album/track controls and source switch SD/Radio.

Where logic lives:
- Main screen updates/state transitions: `doMain.cpp`
- Media data and scan/index: `sd_vendor.cpp`
- Radio transport/status: `radio_vendor.cpp`

## Quick Start (Windows, PowerShell)

Prerequisites:
- ESP32 board package for Arduino (`esp32:esp32`)
- Libraries: LVGL, Arduino_GFX, ArduinoJson, Audio (ESP32), GT911 library exposing `Touch_GT911.h`
- `arduino-cli` installed (PATH or local path used by scripts)

### 1. Build

```powershell
cd C:\project_backup\86switch_onoff_ai
.\build.ps1
```

Optional custom FQBN:

```powershell
.\build.ps1 -Fqbn "esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=max_app,PSRAM=opi,USBMode=hwcdc,UploadMode=default,UploadSpeed=921600"
```

### 2. Flash

```powershell
cd C:\project_backup\86switch_onoff_ai
.\flash.ps1 -Port COM5
```

### 3. Optional asset helpers

```powershell
.\convert_page4_assets.ps1
.\prepare_alarm_melodies.ps1
```

## Network Failure Policy

Implemented behavior:
- Wi-Fi reconnect uses backoff and single connect-task state guard.
- Network HTTP requests are serialized via `net_worker` to reduce TLS heap spikes.
- Weather task:
  - waits for Wi-Fi
  - retries with shorter interval on failure
  - shows fallback texts when unavailable
- Mic donor client:
  - tracks online/offline with failure threshold and grace period
  - pauses polling during transfers

User-visible fallback:
- Wi-Fi disconnected: weather/radio cloud features degrade gracefully.
- Weather unavailable: placeholders stay visible (`Weather loading` / `--`).
- Donor mic offline: status shows `Mic donor offline`.
